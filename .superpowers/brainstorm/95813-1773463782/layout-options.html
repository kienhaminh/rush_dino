How should Context Debug merge into Sessions?

Pick the interaction pattern that feels right. Each approach has different trade-offs.

A

Master-Detail Split

Sessions list stays on the left as a narrow sidebar. Clicking a session loads the full context debug view in the right panel — messages, token bar, tool calls, runs, etc.

Pros

  • Both lists visible at once
  • Instant switching between sessions
  • Feels like an IDE inspector

Cons

  • Session cards lose their rich stat view
  • Less space for context detail
B

Expandable Card (Accordion)

Session cards stay as-is with stats. Clicking a card (or a "Inspect" button) expands an inline context debug panel below it — messages, token details, tool calls. Collapse to go back to the list view.

Pros

  • Preserves existing card stats
  • Contextual — expand only what you need
  • Minimal navigation change

Cons

  • Long page when expanded
  • Less room for message thread
C

Right Slide-over Drawer

Sessions page stays exactly as-is. Each card gets an "Inspect" button. Clicking it slides in a full-height drawer from the right with the complete context debug view — no page navigation needed.

  • Full height = most space for context

Cons

  • Requires explicit open/close gesture
